Where the time went

One frame, pass by pass

A single Epic frame from the same corridor, captured with ProfileGPU in both projects at about the same render size (1.3 megapixels). The scene went from 48.5 to 30.1 ms.

BeforeAfter

Direct lighting stayed about the same: shadowed lights were cut, but more unshadowed fill lights were added for the look. Base pass rose slightly with Nanite; the instancing win is on the CPU, in draw calls. Times from one editor frame, so expect some noise.

The tiers

What each tier does

A C++ quality manager in the map applies each tier at runtime: Unreal's scalability level, the tier's console variables, its post-process volume and its own set of lights. Nothing is written to project config, and everything is restored when play ends.

The work

What I changed

Each figure is tagged with where it came from. One frame is the same-corridor ProfileGPU comparison above; editor and standalone are working measurements taken along the way, so they show the size of a change rather than final numbers.

Static meshes to ISM + Nanite

I wrote an editor tool that converts placed static meshes into instanced static meshes (ISM) and rebuilt the level's structure as instanced Blueprints from one base Blueprint, with Nanite on the meshes. Instancing cuts draw calls; Nanite handles the geometry detail.

~2,500→ ~650 drawsstat unit · separate sessions

Draw and cull distances

Max draw distances on small props, decals and lights, with fade distances on lights so they don't pop. Cull distance volumes handle the rest of the props by size.

Fewer shadows, tighter lights

15 ms→ 4.4 msEpic · editor

Dynamic shadows only where they read, across the whole scene. Smaller attenuation radii and tuned falloff (inverse-square setting and falloff exponent) mean each light touches fewer pixels. In the same-frame capture, shadow depths went from 2.2 to 1.2 ms. Each shadow-casting light renders its own shadow pass and is lit into Lumen's scene; cutting them also took Lumen's scene lighting from 2.9 to 0.4 ms.

Cheaper materials

4.0 ms→ 1.3 msEpic · one frame

Refraction and mirror-like reflective materials kept to the few places that need them, which removed the refraction pass (1.6 ms) and cut the translucency lighting volume from 1.4 to 0.3 ms. Two Sided is off on every master material.

Hardware to Software Lumen

18.9 ms→ 9.8 msEpic · one frame

Software Lumen instead of hardware ray tracing, with scene lighting updates spread over 64 and 128 frames, coarse distance-field tracing, and traced reflections only on shiny surfaces.

TAA instead of TSR

3.8 ms→ 0.96 msEpic · one frame

TSR's cost follows the output resolution and was too high for this GPU. Each tier renders at its own share of a fixed window and TAA upscales it. Post-processing overall went from 5.5 to 2.4 ms.

Texture memory

1.42 GB→ 1.18 GBeditor, includes editor memory

Virtual textures for the materials and virtual lightmaps for the bake, so only the visible parts stay in memory. Then I used the level's Size Map to find the heaviest textures and fixed their compression.

Baked lighting on Apple Silicon

Low and Medium use baked lightmaps. UnrealLightmass runs under Rosetta on Apple Silicon and crashed in Embree; turning Embree off made baking work.

Sun shafts, kept outside

The directional light stays on for its light shafts. Invisible shadow-casting blockers keep it out of the interior.

A Mac-only stall

50–100 ms→ noneEpic · standalone

Mouse-look in fullscreen stalled the frame. Unreal Insights and Xcode Instruments traced it to FMacApplication::OnWindowDidResize forcing a render flush. Windowed mode avoids it.

First-shot stutter

The muzzle flash and impact effects recompiled on first use every session. Impacts now come from a component pool and both effects are pre-warmed at load.

A repeatable benchmark

The pause menu switches tiers and runs a camera-rail flight between Unreal's StartFPSChart and StopFPSChart, so every run is the same path.

Method: each result is one 30.1-second run of the same Level Sequence camera flight in a packaged Mac Development build, 1512×982 windowed fullscreen with VSync on. GPU time and fps come from Unreal's FPS chart logs. The before runs used the original assets in a clean project with no player, enemies or music on screen, which if anything favours them.
